# 行为边界与限制

README 只保留"它是什么、怎么用"。本文件记录行为约束：能力闸门、占用与并发判定、目标身份、恢复记录、续跑语义、外部工具与验证范围，以及与标志注册表核对过的选项表。这些行为发生变化时同步更新本文件。

## 平台能力闸门

每条命令的结果、闸门评估的目标形态以及进程级退出时打印的文本都由[能力矩阵](capability-matrix.md#runtime-gate)生成；本节只说明检查的顺序。闸门在几何计算、锁获取与任何伴生文件创建之前运行，也在影响确认闸门之前运行。缺 `--yes` 的用法检查更早：它在参数解析内、分派之前运行，并以用法错误退出。闸门对每条命令只回答一个问题：命令声明的效果是否为 `write`，以及本宿主是否被列在可写宿主中。写命令在打开目标之前、锁文件存在之前、任何记录目录建立之前就以不支持状态拒绝，拒绝文案点名能写的宿主。`--dry-run` 形态保留声明的效果但不写盘，因此闸门放行，预览仍照常检查。

## 执行放置

写入只有一条路径：一份作业是一串步骤（写表、增删调分区、复制、搬移、建卷/扩缩/属性、刷新内核视图），宿主进程是恢复记录、锁与输出的唯一写者。步骤在哪里执行属于部署细节，每份作业在首次写盘之前决定一次，步骤之间不再改变。

- **原生**：宿主满足本作业所需的全部能力——文件系统层要求的平台/root 权限，以及步骤表解析出的每个外部工具。这份清单与原生执行器读的是同一份工具矩阵。
- **VM**：宿主能力不足，但 `DISKEDIT_VM_BUNDLE` 指向一个通过校验的载体 bundle。整份计划移入 guest；记录、锁与退出码仍由宿主掌握。
- 两者都不满足：以退出码 6 退出，给出缺口与两条出路（安装工具，或提供 bundle）。

闸门决定的不只是能不能：解析出的需求——平台、root 权限与确切的工具清单——在首次写盘之前就决定了放置。因宿主缺少某项能力而转入 VM 的作业，因此是一次已决定的放置，而不是静默回退；没有可用 bundle 时，拒绝路径点名的也是同一项能力。

对未记账写入的防线只有一个点：步骤执行器的 VM 分支。在把步骤交给 guest 之前，宿主先保存该步骤的原像、把状态机置入相应状态，然后才发送；计划循环只通过这一个步骤函数抵达 guest，因此任何步骤到达载体之前，记录必定已经承认「目标可能已被修改」。guest 从不写记录、锁或退出码。guest 侧参数同样不属于这一承诺：目标是文件描述符，token 与会话边界见下。

bundle 目录包含 `manifest.json`、`kernel` 与 `initramfs`。清单声明 `schema`、`arch`、`binary_version`，并为每件制品给出相对 `path` 与 `sha256`；可选的 `worker.sha256` 把 worker 映像固定为本可执行文件。只有以下全部成立才接受：schema 是当前版本、架构与本进程一致、`binary_version` 与本可执行文件版本一致、每件制品的路径都落在 bundle 目录内、每个 SHA-256 都对得上。任何一项不符都在启动 QEMU 之前拒绝——宿主不会把目标交给身份不明的 guest。

启动器把已打开的目标经文件描述符交给 QEMU（`-add-fd` 加 `/dev/fdset/`），通过 `-blockdev` 交给块层、缓存固定为 `cache.direct=on`，以 virtio-blk 按目标的逻辑扇区大小（512 或 4096）呈现，协议走串口控制台，熵由 virtio-rng 提供。QEMU 自身的退出状态只描述虚拟机如何结束；某一步是否落盘由协议的 `result` 在 guest 自己完成回读核对之后回答，不看该状态。

把宿主与同一管道上的陌生人分开的是会话边界，而不是 token。一次性 `DISKEDIT_WORKER_TOKEN`（从 `DISKEDIT_WORKER_TOKEN` 读取，经内核命令行传给 guest，因为 guest 侧引导脚本不在本仓库内）只在 `hello` 帧校验一次。worker 随后用 128 位进程熵生成的会话 id 回答 `ready`，**之后每一帧都必须回显该 id**（协议版本 3）；宿主在唯一的发送路径里补上它，所以新增帧类型不可能漏带。该 id 只经 stdout 从 guest 传向宿主，因此即便某一方对 worker 的 stdin 有写权限（这正是 token 唯一拦不住的一方），也无法构造出 worker 接受的帧。缺少该 id 的帧以协议错误结束会话，目标不受影响。

## 占用边界

对块设备的写入依赖以 `O_EXCL` 打开整块磁盘：只要有分区处于挂载状态或用作 swap，内核就以 EBUSY 拒绝打开；写入前还有第二道占用闸门再检查一次（在块设备上逐个探测分区——纵深防御）。镜像文件没有这种内核语义，因此闸门反向枚举 loop 设备：把已打开的镜像句柄的 `(st_dev, st_ino)` 与 `LOOP_GET_STATUS64` 返回的 `(lo_device, lo_inode)` 比较；匹配时检查该 loop 及其分区是否已挂载（遍历每个可读的挂载命名空间）、是否为活动 swap、是否被块设备栈持有。判定不依赖 `loop/backing_file` 路径，因此硬链接别名、已删除的 backing 路径以及其他挂载命名空间中的挂载都能被发现。本进程登记的 loop 排他性是进程级名字表；每个条目被消费时都对照当前活动的映射重新检查（名字只用于定位登记项）。占用判定匹配每个 backing 具有该文件 `(st_dev, st_ino)` 的 loop，因此它回答的是"该文件已被映射或被持有"，而不是同一文件系统上多个叠加映射中哪一个是它。**直接写表的命令**（`new`/`add`/`delete`/`set name|type|flag`/`undo`/`replay`/`release`）要求目标完全空闲：任何分区在使用都会使新表与内核视图分叉，因此该命令不关心它编辑的是哪个分区。`copy` 是例外——它只在重叠检查之后向空闲区域添加一个条目，不改动任何既有区间，也不移动任何分区的区间。移动类命令（`resize` 的每种形式——`--end`、`--grow-to-end` 或给定尺寸——以及 `move`）与 `mkfs` 按写入的形态区分：保持起点、只延长末端的写入在仅被 dm 持有的目标上允许（LVM PV 与 dm-crypt 的增长语义）；移动、收缩与整段重写一律拒绝。若任何被枚举的 loop 节点无法打开、ioctl 返回 ENXIO 以外的错误、sysfs 无法读取，或因权限原因无法读取 `/proc/<pid>/mountinfo`（例如 `hidepid`），工具拒绝写入（退出码 4），按"无法确认"处理——即使该 loop 与目标无关；这是安全优先的环境限制，不是目标正在被使用的证据。

## LVM 收尾边界

镜像内 PV 的 `pvresize`/`lvextend` 通过临时 loop 映射执行。如果该 PV 已被另一个 loop 映射且 VG 有活动 LV，LVM 更倾向于设备视图"in use by an LV"而不是临时映射，因此针对临时映射的 `pvresize` 不生效（退出状态仍为 0）。工具从后置条件检查报告退出码 5（后置条件视图陈旧）并打印补救办法；它不会宣称成功。分区表扩展已经提交；PV、LV 与文件系统未变。要在该配置下走完 LVM 链，先停用 VG、释放用户侧 loop 再重新运行。工具不会提升由另一层拥有的 loop 的 `sizelimit`：当外部 loop 的偏移与请求相同但 `sizelimit` 不同（更高或更低）时，它拒绝，并指向从拥有该映射的层解绑再重新绑定（`losetup -d <dev>`，让该栈重新映射）；`--grow-lv` 同理——没有这次重新绑定，拥有者不会替你走完 LVM 链。

对镜像内 PV 成功执行 `--grow-lv` 之后，`lvextend -r` 会让此前处于非活动状态的 LV 保持活动，因此临时 loop 无法立即解绑：`losetup -d` 返回成功，内核把该 loop 标记为 autoclear，映射在 VG 停用时（`vgchange -an`）才被释放。这是临时映射的生命周期，不是泄漏；VG 停用后，`losetup -a` 不再列出该镜像。

## 并发边界

对目标的排他锁是*建议性*的：它只约束遵循 DISKEDIT 协议的进程，且只在它们的各次调用之间生效。**它不是针对系统上每个写者的强制锁**，不会阻止其他程序、内核侧写入或绕过本工具的路径写入同一目标；不得把它读作系统级的排他保证。整盘 `O_EXCL` 与挂载占用闸门只在内核语义内阻止写者。镜像的 loop 反向查找是写入前的时点判定：在检查与实际写入之间，外部进程仍可创建 loop、启动 swap 或挂载该镜像，而本工具的锁不约束这些进程。写表在解析时读取一次表，并在提交时把该快照写回；提交前它重新读取条目数组并逐条与快照比较（本层编辑过的槽位可能已等于目标值），任何条目不同就拒绝写表，因此外部进程在窗口期内所做的改动不会被静默覆盖（修复步骤使用同一规则，覆盖添加、设置与删除，以及整条重定位与 resize 路径）。要与其他写者共享目标，请在外部串行化。inode 级第二凭据仅在 Unix 上获取；非 Unix 平台只承诺锁文件。硬链接、符号链接与 junction 别名各自获取自己的锁、各有各的场景；经别名并发使用不在支持边界内（`std::fs::File::try_lock` 在 Windows 上是强制性的整文件锁，不能代替该凭据）。

## 设备身份边界

恢复记录对每个目标都位于 `<state_root>/images/<key>/record`——镜像与块设备相同；`<key>` 是目标 32 字节身份指纹的前 16 字节小写十六进制，锁是同目录下的 `record.lock`，因此一个目标只有一份记录与一把锁。指纹是 sha256 对“类别标签加该类别的字段”的结果：镜像用 `file\0` 加上 Unix 的 `(st_dev, st_ino, len)` 或 Windows 的 `(卷序列号, 文件索引, len)`，因此同一 inode 的两个硬链接共用一个记录目录，而在同一路径替换或重建文件会得到新的身份——经一个硬链接中断的任务可经另一个续跑。块设备依次取 `wwid`、`device/serial`（序列号仅在两次读取一致时采用）、`dm/uuid`、`md/uuid` 中第一项可用的值，再加上设备长度以及分区节点自身的起点与长度；因此分区节点与整盘节点各有自己的记录目录。loop 设备没有这些 UUID，改用承载文件的身份加上映射偏移、上限与分区位置。sysfs 拓扑或类别材料读不到时身份为 `Unusable`：没有记录目录，写命令以退出码 6 拒绝，且不会退回用调用方路径拼出的名字。`--alias NAME` 只对自身证明不了身份的块设备构成身份：它用四条带种子的 FNV-1a 把名字展开到同一个 32 字节键空间，在镜像与自身能证明身份的设备上被拒绝。状态根在设置了 `$XDG_STATE_HOME` 时为 `$XDG_STATE_HOME/diskedit`，否则 Unix 为 `~/.local/state/diskedit`、Windows 为 `%LOCALAPPDATA%\diskedit`；没有状态根的宿主没有记录目录，写命令拒绝。

## 恢复场景的身份检查

记录在载荷前缀里声明自己属于哪个场景；续跑、回滚与回放的每条路径在写入之前都用当前目标复核这份声明。

- **目标指纹。** 前缀存目标的 32 字节指纹。恢复按 `Fingerprint::matches` 比较：双方都是 `Strong` 且 32 字节相等。指向别的目标的记录按需要人工处理拒绝；打开既有记录的会话也按"属于别的载体"拒绝。
- **长度代次。** 前缀存长度代次，即目标总字节数经 FNV-1a 展开并置最低位的结果。恢复按目标当前长度重算；零值或取值不同都拒绝，因此针对另一长度记下的偏移不会被回放。扇区尺寸不参与比较：记录里的偏移是字节偏移，只受容量约束。
- **计划摘要。** 前缀存 32 字节计划摘要。只有与本次计划的请求摘要（跨次重跑保持不变的那个摘要）相等时才复用未终结的记录；属于别的计划的记录拒绝，不并入本次作业。
- **持锁后的身份复核。** 执行器取得记录锁后再次探测目标身份：读到 `Strong` 就必须与计划指纹相符；由用户声明名构成身份的计划，只在目标仍证明不了自身身份时成立。

容量、挂载状态与 loop 映射在记录里没有独立副本：这些字段参与身份时已是指纹的一部分，无法组成同一指纹的目标由指纹核对本身拒绝。

## 记录格式

记录是 16 字节头加一段载荷：头由 magic `DREC`、载荷长度、载荷 CRC 与覆盖前 12 字节的头 CRC 组成，没有单独的版本字段。载荷以固定前缀开头——目标的 32 字节指纹、长度代次、32 字节计划摘要，以及覆盖该前缀的 CRC——随后是帧。长度代次由目标总字节数经 FNV-1a 展开并将最低位置一；零表示记录不带长度证据。恢复时把记录中的指纹与当前目标比较，并按目标当前长度重算长度代次：零值或取值不同都按需要人工处理拒绝，因此针对另一长度记下的偏移不会被回放。magic 不是 `DREC` 的记录按外来记录报告，从不解码；会写盘的命令以拒绝状态拒绝它，`release` 则把它归档为同目录下的 `record.<N>.abandoned`。

## 恢复记录的位置

恢复记录是其位置上的一类普通文件（`<state_root>/images/<key>/record`；锁是同目录下的 `record.lock`，其中不含记录）。该位置上是什么由一次探测回答：不存在、可解码、已损坏（部分写入或 CRC 不匹配）、无法识别的格式（magic 不是 `DREC`）、不是恢复文件（符号链接 / 目录 / 非普通文件），或不可读。在 Linux 上，路径以父目录为锚点，用连续的 `openat(O_NOFOLLOW|O_DIRECTORY)` 解析，最后一级用 `O_NOFOLLOW`：任一级为符号链接、非目录，或最后一级为非普通文件，都算"不是恢复文件"。其他平台用 `symlink_metadata` 探测，只读取普通文件：最后一级是符号链接、目录或其他对象时一律报告为"不是恢复文件"。删除与重命名作用于该路径条目本身（父目录 fd 加相对名字），不跟随链接、不改变链接目标；原子替换是同目录内的重命名。当条目不是恢复文件，或删除失败时，场景被视为仍然存在，工具不会报告其已清理。

## 本版行为变更

以下是刻意保留的用户可见变化；本版之前的构建行为不同：

- **写入受目标此刻长度约束。** 会越过普通文件此刻长度的写由平台、载体协议（按声明的盘长）与 worker 在落盘前三层拒绝；写通道还会按声明区间复核目标长度，并回读每个已写分段。
- **符号链接不是记录。** 记录位置在路径任何一级是符号链接时都报告为"不是恢复文件"；工具不会穿过它读取、替换、删除或改名。
- **自相矛盾的备份头按损坏处理。** GPT 备份头的反向指针与副本位置不一致时，报告为损坏，而不是当作"没有表"。
- **其他版本的记录按外来格式处理。** 记录格式标记为 `DREC`；标记为其他值的记录一律报告为外来记录，不会被读取。
- **写目标需要能写的宿主。** 声明效果为 `write` 的命令在可写宿主之外以不支持状态拒绝，且发生在打开目标之前；只读入口照常运行，`--dry-run` 预览仍可用。
- **不可逆步骤不能撤销。** 记录里出现不可逆步骤时，`undo` 拒绝把目标回滚；`replay` 仍可只恢复记录中的分区表区间。

## 续跑边界

重新运行原命令会从其恢复记录续跑，适用于 `new`、`move`、`resize`（每种形式：`--end`、`--grow-to-end` 或给定尺寸）、`mkfs`、`resize --fs-only` 与 `set`；GPT 与 MBR 共享同一记录族，因此中断的 MBR 扩容以同样方式续跑，`undo` 会把记录中的表写入回滚。在线 resize（块设备且分区已挂载）改为经由工具写入：没有可续跑的内容，`undo` 也无法回滚。`add`、`delete` 与 `copy` 没有续跑路径（`help copy` 注明 `No resume`），因此重新运行前先用 `undo` 回滚，或用 `DiskEdit release` 释放场景。收缩步骤记录三种状态（未收缩 / 已验证 / 未验证）：当文件系统大小无法读回时，任务在收缩步骤停下，并以退出码 5 报告未完成的事务，重新运行时先读取实际大小，确认收缩从未发生后才再次执行。ext2/3/4、ntfs 与 btrfs 的扩容会读回；f2fs、xfs 与 vfat 没有读回，因此成功的扩容仍为未验证：该次运行打印一条点名尺寸检查的待办项并以 5 退出。结束时只有在六个条件全部成立才删除恢复记录：记录可识别、其提交状态为已提交、身份匹配、持久性已确认、后置条件读回通过，且表写入步骤已完成。否则保留记录，并打印 `the recovery record was not cleaned up (<reason>) — release it with DiskEdit release`。删除本身失败时，事务以退出码 5 报告，而不是成功。搬移的数据按批次同步并推进持久游标（同步先于记录推进，游标永不超前于实际落盘的字节）；批次大小随提交延迟自适应，因此崩溃后最多重做 256 MiB 的已复制数据，大于该窗口的块尺寸退化为逐块提交。自我重叠的搬移（位移小于源区间）在所有路径上都逐块提交——按批次缓冲的块会伸入重做区间，而重做会读到被同一批次覆盖的源数据。

## 工具行为与判据

写表之后内核不会自动重读。重读先走 `partx -u`；`BLKRRPART` 只在能按整盘打开时使用，任一分区挂载或用作 swap 时它以 `EBUSY` 失败，新增与删除再逐分区用 `BLKPG` 补齐。重读失败不等于表没变：它只降级为"内核视图待同步"，写入是否成立由回读目标字节回答。

ext 扩容的落点按块组取整。末段装不下完整块组时 `resize2fs` 会整段留空——1.47.x 把 400 MiB 卷扩到 900 MiB 会止于 896 MiB——所以"扩到区间末端"的判据是末端落在最后一个单元内，不是字节相等。扩缩前先跑 `e2fsck -fp`；它退出 1 表示已修复，可以继续，只有更大的退出位才中止。

NTFS 卷把卷起点写在引导扇区偏移 `0x1C` 的 `HiddenSectors`。平移后主扇区与卷尾最后一扇区的备份都要写成新起点；只改主扇区会让 NTFS 检查器判备份损坏。改写前核对两处签名，任何一处不符就不写字节。缩放先试 `ntfsresize`；被"卷不干净"拒绝时跑一次 `ntfsfix` 再重试，重试仍失败则保留首次错误。

loop 节点可能陈旧：占用与挂载判定不信任 `/dev/loopN` 的名字或 `backing_file` 路径，一律用 `LOOP_GET_STATUS64` 返回的 `(lo_device, lo_inode)` 与目标句柄的 `(st_dev, st_ino)` 比对；名字只用于定位登记项。

## OpenWrt 组合布局

同一分区内是只读的 squashfs/erofs 根加上尾部的 RW overlay：扩容时识别内层文件系统，并仅通过偏移 loop 扩展 RW 层，且只扩容；内层文件系统不是 ext 或 f2fs 时拒绝。尚未格式化的尾部 RW 层（首次启动安装场景）不算失败：分区照常扩容，该层在首次挂载时由 fstools 初始化，此处无事可做。多设备 btrfs 的扩容被拒绝。

## 验证范围

工具以 Linux `util-linux` 和各文件系统官方工具的命令行契约为准，不绑定某个发行版；回归套件（`tests/wsl/`）在 Ubuntu 上以 `util-linux` 2.41.3 验证过，其他发行版与版本未验证。占用探测记录在下面的等级中；未运行过的路径不会被描述为通过：

| 证据等级 | 内容 |
|---|---|
| 已运行并验证 | loop 身份编码（`st_dev`/`st_ino` 对照 `lo_device`/`lo_inode`）、未绑定 loop 的 `ENXIO`、硬链接别名与已删除的 backing 路径、其他挂载命名空间中的挂载、loop 与分区挂载、活动 swap、sysfs holders、已退出进程的 mountinfo（`EINVAL`）、失败即拒绝的探测（退出码 4）、在没有持有者的 LVM PV 上完整的 `--grow-lv` 链、活动 LV 持有分区时 `AllowDm` 不被通用规则拒绝（链到达 LVM 步骤）而整段 `mkfs` 重写仍被拒绝、在已挂载镜像上 `new`/`add`/`delete`/`set name\|type\|flag`/`undo`/`replay`/`release` 全部被拒绝且磁盘字节不变、多个 loop 匹配时点明实际持有者的拒绝、非 root 用户可用的镜像操作（该用户无法打开 `root:disk` loop 节点） |
| 未验证 | 容器内独立 PID 命名空间下 loop 枚举的完整性；因 `hidepid` 等权限限制导致 mountinfo 不可读的部署（代码按探测失败拒绝，但未在真实 `hidepid` 环境中运行过）；上表以外的发行版与内核版本；**镜像内 PV 被另一个 loop 映射且 VG 有活动 LV 时完整的 `--grow-lv` 收尾链**（见上一节：LVM 的重复 PV 规则使针对临时映射的 `pvresize` 成为空操作，工具报告退出码 5 而不宣称成功） |
| 设计限制 | 占用闸门是写入前的时点判定，不阻止检查之后创建的外部 loop / swap / 挂载；镜像侧枚举只覆盖本进程可见的 loop 节点，因缺少权限（`root:disk`）而无法打开的节点按未绑定跳过——创建绑定与访问节点需要同一权限类别，因此这类用户无法为该镜像创建绑定；不存在的节点、`ENODEV` 以及其他无法确认身份的情形按探测失败拒绝，该边界随内核/udev 的权限模型移动；失败即拒绝同样适用于无关 loop 的探测失败；缺失的记录项（`None`）不参与比较 |

## 选项

命令接受哪些选项由 `DiskEdit help <CMD>` 定义；下表列出每个选项及其取值形式。取值列写作 `—` 的选项不取值。

| 选项 | 取值 | 含义 |
|---|---|---|
| `--align` | A | 放置对齐：`mib` 或 `none`（默认为 `none`，即给定时所用的 LBA；由 `add`、`move`、`copy`、`resize --end` 与 `resize --grow-to-end` 接受；对 `resize` 作用于计算出的末端） |
| `--allow-move` | — | `resize` 在 GPT 上可以搬移阻碍操作的分区 |
| `--chunk` | MiB | `move`、`copy` 与 `resize` 的恢复粒度（MiB，1..=64）。续跑的任务省略该选项时沿用记录中的值，新任务使用 4；显式值与记录不同则拒绝。路径无法搬移时拒绝：MBR 的 `resize`、在线 `resize` 与 superfloppy 的 `resize` |
| `--discard-replay` | — | 当记录仍含有可回放区间（或载荷已损坏，或条目数未知）时，`release` 必须给出该选项；仅 `release` 接受 |
| `--dry-run` | — | `resize` 打印算出的范围、文件系统步骤与任何搬移计划；`add` 打印新分区的落位。两者都在第一次写入之前停下，不建记录，也不需要 `--yes` |
| `--end` | LBA | `resize --end` 的结束 LBA |
| `--fs-only` | — | 仅 `resize`：不改分区表，只动文件系统——离线 `<TARGET>:N` 把文件系统长满所在分区；`<MOUNTPOINT> [BYTES]` 经挂载卷在线扩容 |
| `--json` | — | 仅 `layout`：输出结构化逐分区明细，替代文本布局 |
| `--grow-lv` | — | `resize` 在 LVM PV 上继续进入 LV 及其文件系统 |
| `--grow-to-end` | — | `resize --grow-to-end` 把末端固定在可用空间的末尾 |
| `--alias` | NAME | 为不带 WWN、EUI 或可重复序列号的目标（`nbd`、`rbd`、`dm`、`md`）命名；所有写命令、`release` 以及 `records show` / `records list` / `records verify` 接受，只读命令用它定位与核对记录。回滚、回放、放弃或核对该记录都需要同一个名字；镜像与自带身份的设备拒绝该选项（退出码 2） |
| `--keep-partuuid` | — | `copy` 复用源 PARTUUID |
| `--label` | S | `mkfs` 写入的文件系统标签（省略时为空标签；不虚构默认值） |
| `--lv` | NAME | 配合 `--grow-lv` 要扩容的 LV（省略时为该 PV 上唯一的 LV） |
| `--name` | S | 分区名 |
| `--no-fs` | — | 仅 `resize`：跳过扩容分区的文件系统步骤 |
| `--overwrite-data` | — | `new` 授权覆盖落在新表元数据区域内的旧分区的字节 |
| `--part-number` | N | `add` 的条目槽位（从 1 起，必须空闲；省略时为第一个未使用的槽位） |
| `--random` | — | `set uuid` 要求目标生成新值：ext 用 `tune2fs -U random`，xfs 用 `xfs_admin -U generate`，btrfs 用 `btrfstune -u`；swap 没有生成形式，NTFS 序列号不是 Windows 卷 UUID |
| `--root` | ROOT | 仅 `records list`：扫描一个记录容器目录，而不是列目标自己的记录 |
| `--sector-size` | N | 镜像逻辑扇区大小（2 的幂，至少 512 字节；65536 字节上限是实现限制，不是格式要求）；对 `copy` 作用于一个目标 |
| `--start` | LBA\|end\|align | 起始 LBA；仅 `add`、`move` 与 `copy` 接受。对 `add` 可省略（能容纳 SIZE 的第一个空洞）；`move` 与 `copy` 必须给出，也接受 `end`；`align` 只有 `move` 接受（从当前起点向上取整到下一个 1 MiB 边界）。`resize` 只改变末端——搬移是 `move` |
| `--table` | gpt\|mbr | `new` 创建的分区表类型 |
| `--type-guid` | GUID\|0xNN | `add` 的分区类型：GPT 取标准 GUID 文本（省略时为 Linux filesystem data）；MBR 取两位十六进制类型字节（省略时为 0x83） |
| `--yes` | — | 写入前的确认闸门：`new`、`add`、`delete`、`move`、`copy`、`resize`、`mkfs`、`set`、`undo`、`replay` 与 `release` 要求给出，缺失时在解析阶段以退出码 2 退出；其他命令（`layout`、`records list/verify/show`、`check`）不接受 |
