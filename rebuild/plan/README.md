# rebuild

`rebuild/` 是一个完整项目：`Cargo.toml`、`src/`、`crates/core/`、`tests/`、`docs/`、`LICENSES/` 与仓库同形。仓库根目录的现有实现是**行为基线**，定义"重写后必须与之一致"的对外行为，只读参考，不改动。

`plan/` 是本目录的规划文档，不参与构建，也不被代码或注释引用。

## 任务

在 `rebuild/` 内独立实现同一个程序，满足三件事：

1. **行为等价**：命令面、退出码、机器可读输出、盘面效果、记录可恢复，五项与基线一致；差异只允许 `plan/01-目标与边界.md` 第 5 节列出的那些，且每条带测试。
2. **结构封闭**：`plan/01-目标与边界.md` 第 4 节的十项不变量，每一项都靠类型或唯一构造点成立，而不是靠注释或人工检查。
3. **干净自洽**：代码与注释只描述当前行为；不引用规划文档、历史版本或仓库根目录的材料。任何人只读代码与注释即可理解，不需要背景。

## 边界

**`rebuild/` 之外一律只读。** 仓库根的 `src/`、`tests/`、`Cargo.toml`、`docs/`、CI 配置、`.trae/` 都只是参考与行为基线：不修改、不删除、不重命名、不格式化、不新增文件。交付时 `git status` 只允许出现 `rebuild/` 下的路径。

**`rebuild/` 之内完全自由。** 目录、模块、类型、依赖、状态机、记录布局、测试与构建配置都按最优方式写，不受外部实现的组织方式约束。

**冻结的只有意图与最终效果**：怎么用（命令、参数、默认值、值域、互斥、确认与撤销、帮助入口）与用了以后得到什么（退出码、输出字段与语义、盘面效果、记录可恢复性）。实现内部的一切选择不属于冻结范围；要让用法或结果发生变化，必须登记为 `plan/01-目标与边界.md` 第 5 节的差异并附撤回条件。

另外两条同样属于边界：不读取外部实现写下的记录（记录格式由本实现定义，不匹配即按外来记录拒绝）；`rebuild/` 内每种能力只有一条实现，不留过渡期双路径。

## 阅读顺序

| 顺序 | 文件 | 内容 |
| --- | --- | --- |
| 1 | `plan/01-目标与边界.md` | 等价定义、不变量、刻意差异、完成标准、停工条件 |
| 2 | `plan/02-架构.md` | 项目结构、模块、类型、唯一构造点、状态机、记录格式、代码约定 |
| 3 | `plan/03-行为基线.md` | 必须复现的命令、退出码、输出、盘面与恢复行为 |
| 4 | `plan/04-任务与验收.md` | 有序任务、每步静态判据与拒侧用例、测试层次、依赖顺序 |
| 5 | `plan/05-静态自检.md` | 交付前逐项填写的核对表 |

## 怎么开始

1. 读 `plan/01` 与 `plan/03`，把命令面、退出码、输出字段、盘面与恢复行为逐项落到代码里。
2. 读 `plan/04`，按 T0–T17 的静态判据**一次写完**全部能力，不按"写一部分验一部分"推进。
3. 交付前填 `plan/05-静态自检.md`：逐项写明代码里靠什么机制成立。

## 交付方式

能力一次写全，重档验证挡在写循环之外；验收由人读代码完成。

- 提交在仓库的 `test` 分支，按批次提交；是否推送由用户决定。
- 分多批写，每批由多个子代理并行，各自负责互不重叠的文件；公共类型与模块边界先由主执行者落定。
- 每批结束跑编译档（`cargo check`、`cargo clippy -D warnings`、`cargo fmt --check`）与纯核档（`core` 单元用例、`trybuild`、命令面用例）；这两档无 IO、失败定位到行，是修根因最便宜的时机。
- 重档（release 构建、全量测试、镜像与特权用例、等价对照）全部写完后跑一次；在 `plan/05-静态自检.md` 记「未执行」，写明在有 root 的环境补什么命令能验。
- 代码里不留任何"验证用"的临时代码、开关或占位实现；不留被注释掉的旧写法。

## 硬性禁止

- 禁止用文本扫描代替类型约束（"某写法不得出现"这类检查只在无法类型化时保留，且须写明替代不了的类型是什么）。
- 禁止用脚本或测试复刻产品语义；测试只消费结构化输出与独立 oracle。
- 禁止进程全局状态（thread-local、静态可变、编译期路径常量）承载判据。
- 禁止"写盘之后仍能得出未改动"的路径。
- 禁止在代码或注释里出现"原实现""改为""兼容""迁移""v2"这类叙事。
