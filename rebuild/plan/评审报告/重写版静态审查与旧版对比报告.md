[D1-C1 · 成员：A1b-A3、A1b-A7、A1b-A11、A3-02、A6-05、A2-07、A4b-10] — 几何/偏移算术未做 checked 运算，或上界未在目标侧重算；上界来源为计划值/源侧/裸 u64 运算（S3）

## 3 同一处改动（方向，不落地修复）

> 口径：本节只给改动方向与归并依据，不写修复代码、不评取舍。依据来自 part-A 的四个改动簇（G1–G4）与 lane-B11 的五条根因归并（A–E），以及 D1–D8 正文中已落位的发现编号。**不存在单点改动能覆盖多数 S1/S2**：以下按共享根因分为 7 个改动簇；簇内成员必须一起改，单独修某一条只会把风险挪到同层另一处。

### M1 占用 / 身份 / 容量探测结果收口为显式三态
- 依据：part-A G1；D5-C1、D5-C2、D5-C3、D7-C5 部分成员；S2：A5b-01、A5b-02、A5b-04、A5-07。
- 改动方向：占用、身份、容量探测结果收口到一处显式三态（空闲 / 占用 / 不可判定），NotFound、I/O 失败、权限拒绝、不适用分别成态，禁止把 NotFound 折叠为空集、禁止把 Absent 折叠为 Unknown；设备身份归一（设备号 / canonical 路径 / kname）收口到单一模块；容量探测失败与「容量为 0」分态。
- 为什么是同一处：共同根因是「未知」没有类型化表示，失败靠 Result 携带、空值靠派生默认；五路占用与指纹/容量探测各自折叠，调用方无从区分「查不到」与「查到没有」。
- 联动面：占用视图、拒绝文案、退出码映射、JSON 输出三态形状需随三态同步；调用方必须显式处理不可判定态。
- 静态置信边界：本簇结论为静态阅读推断；各探测原语在真实容器/内核版本上的返回语义未动态验证。

### M2 记录持久化契约补齐：存在性 / 属主 / 三态 / 许可 / 删除前回读 / 目录 fsync
- 依据：lane-B11 根因 A；D3 S2：B11-F01、B11-F04、B7-01、B7-02、B7-03、B7-04、B6-F-01。
- 改动方向：记录存储层重写旧版 `recovery/journal.rs`、`recovery/cleanup.rs` 承担的失败分类与删除防线——记录存在性、属主核对、重开冲突、三态结果；清理/删除前的许可核对、留存期、删除前回读匹配、目录 fsync；解码侧校验原像 len/data 一致或由 kind/flag 显式区分不可逆空原像；recover 路径先过占用闸与 core 冲突判定。
- 为什么是同一处：两者同属 `platform/linux/records.rs` + `source/guarded.rs` 这一层记录持久化契约；防线缺失与分类缺失会在同一删除/恢复接缝上互相放大。
- 联动面：recover 签名与上层调用、记录格式兼容策略需同步；旧记录字节流是否可读取决于格式取舍（见 B6-F-01）。

### M3 持久记录承载续跑游标与核对基准
- 依据：lane-B11 根因 B；part-A G3；D3 S2：A1-04、A2-03、B11-F02、B11-F03、B11-F11；D3-C1、D3-C2。

### M5 长度 / 落点几何在目标侧重算并单点化
- 依据：part-A G2；D1 S2：A1b-A1、B12-F1、B12-F2；D4 S2：A1b-A2、A1b-A13、A4b-02、A4b-03、A4b-04；D6 S2：A1b-A10；D1-C1、D4-C1、D6-C4。
