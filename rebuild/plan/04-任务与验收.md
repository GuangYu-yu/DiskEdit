# 04 任务与验收

每个纵切独立成批、独立回退。编译档与纯核档每个纵切都真跑，不靠读代码判定；需要镜像、特权或基线二进制的档在 Linux 机器上跑，没有结果记录的一律记「未执行」，未执行的不得交付。任务里的"不产出"未清，该任务不算完成。执行顺序、分工与门禁命令见 `06-防漂移执行手册.md`。

## 1. 项目约定

验证分三档，只有第三档挡在写循环之外。

| 档 | 内容 | 时机 |
| --- | --- | --- |
| 编译档 | `cargo check --all-targets`、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check` | 每批 Tn 结束 |
| 纯核档 | `crates/core` 的属性/编解码/前缀恢复用例、`tests/ui/` 的 trybuild、`tests/contract/` 的命令面用例 | 每批 Tn 结束 |
| 重档 | `cargo build --release`、全量 `cargo test`、镜像与特权用例、等价对照 | 每个纵切结束，在 Linux 机器上跑；结果落 `plan/evidence/` |

| 项 | 值 |
| --- | --- |
| 构建 | `cargo build --manifest-path rebuild/Cargo.toml`（重档） |
| 测试 | `cargo test --manifest-path rebuild/Cargo.toml`；涉及 loop、块设备、挂载、虚拟机的用例需 root 与镜像（重档） |
| Lint | `cargo clippy --manifest-path rebuild/Cargo.toml --all-targets -- -D warnings`；`wildcard_enum_match_arm` 必须启用（编译档） |
| 格式 | `cargo fmt --manifest-path rebuild/Cargo.toml --check`（编译档） |
| 不要动 | `rebuild/` 之外的一切：仓库根的 `src/`、`tests/`、`Cargo.toml`、`docs/`、CI 配置、`.trae/` 一律只读 |
| 状态词 | 只能用「待执行 / 未执行 / 已通过 / 未通过」；未跑过的写「未执行」并写补什么能验 |
| 交付纪律 | 一次一个纵切；不在纵切之间做行为性返工；不留占位与开关 |

### 1.1 防补丁三条

1. **`allow` 只许局部且带理由**。禁止 crate 级或全局 `allow`，禁止为消错调低 lint 级别；`allow` 条数记入 `05-静态自检.md`，数量上升须说明原因。
2. **`clippy`、`trybuild`、纯核用例红了只修根因**。动手前先写一句"这条错误对应哪条不变量或哪个类型约束"，再决定改哪一层；不允许放宽断言、修改期望值或跳过用例来变绿。
3. **用例失败按子系统整体重写**，不在原地打补丁。先判断是判定层、执行层还是档案表的结论错了，再从那一层重述。

这三条与第 7 节的未通过清单、双 oracle、判据自验同属"防为绿而改"的闸；只有真的跑过才会触发，所以编译档与纯核档必须每批执行。

## 2. 执行与提交

- **仓库**：提交在仓库的 `test` 分支；是否推送由用户决定。
- **阶段**：按 T0–T17 的阶段顺序推进；阶段内按 `06` 定义的纵切逐个完成，每个纵切一个提交；提交信息写清本纵切范围与本纵切不产出的形态。
- **并发**：不按文件并行。同一时刻只有一个纵切在写；可以并行的是互不依赖的填表与用例枚举。按文件切分会让每份文件局部合格、却没有谁对跨模块的不变量负责，这条路径明确关闭。
- **合并前**：跑 `06` §5 的全部门禁，结论以 `plan/evidence/*.log.json` 为准；任何一项没有记录或未通过，不合并。模型口头说“已核对”不是依据。
- **纵切出口**：编译档与纯核档零失败；重档有结果记录且通过数达标。
- **提交边界**：一次提交只做一类改动；回退时只回退该提交。

### 2.1 git 规范

首次提交之前先落 `rebuild/.gitignore`，最低集合：

```gitignore
/target/
**/*.img
**/*.raw
**/*.qcow2
*.log
*.tmp
tests/artifacts/
plan/baseline/images/
.idea/
.vscode/
*.swp
.DS_Store
```

**不得入库**：构建产物、镜像与二进制样本、测试运行产物、日志、临时脚本、编辑器与系统文件、凭据、下载的第三方源码或工具。基线只提交文本（命令清单、判定行、差异表、镜像配方），镜像本身记生成方式而不入库。

**必须入库**：`Cargo.lock`、`docs/{en,zh}` 的产品文档、`plan/` 的规划文档、`tests/ui/` 的编译失败用例与期望文件。

**提交粒度与信息**：

- 一次提交只对应一个任务或一类改动；格式化、重命名、行为改动分开提交；`plan/` 文档与代码分开提交。
- 信息格式 `S{纵切号} 范围: 做了什么`（纵切号见 `06` 附录 B），正文写不产出与影响面；禁止 `wip`、`tmp`、`fix`、`update`、`杂项`。
- 每个提交不留被注释掉的代码、调试输出、占位实现、未使用的依赖。
- 历史按任务编号推进，不出现"先写后删再写回"的往返提交；无远端，不改写历史，也不 `--amend` 掩盖错误提交——错了就新提交说明，保持可追溯。

**嵌套仓库**：`rebuild/.git` 与仓库根的 git 互不相干；根目录 `git status` 只应看到 `rebuild/` 一个未跟踪项，根目录零改动这条不变。

## 3. 任务

每个任务列三项：产出物、**不产出**（本任务不得留下或引入的形态）、验证方式。新项目没有旧实现可删，"不产出"约束的是本任务自己写下的东西。

### T0 冻结能力基线（只读源码，不运行、不改 `rebuild/` 以外的代码）

- 产出：`plan/baseline/commands.md`、`json/`、`judgment-lines.md`、`images.md`、`divergences.md` 骨架、`plan/baseline/README.md`（取数命令原文与产物清单；一次性命令不入库，比对器是 `rebuild/tests` 下的 Rust 用例）。
- 内容：命令面逐项从声明读出；文件系统矩阵逐格从能力表读出；四种目标形态；退出码从判定分支读出；载体入口完整性。
- 验证：每条结论都指得到源码位置（文件与符号名）；指不到的记「未执行」并写明补什么能验。
- 停工：任一项在源码里找不到判定依据 → 停，列缺项。

### T1 项目骨架

- 产出：`rebuild/Cargo.toml`（`[package]` 为 `lib + bin`、`[workspace] members = ["crates/core"]`、`[lints]`，不声明 `rust-version`）、`crates/core` 空库、包根 `src/lib.rs` 与 `src/main.rs`、`platform`/`app` 两个模块树入口、`trybuild` 与三条占位失败用例、独立 CI 作业。目录与文件划分按 `02-架构.md` 1.2。
- 配置整理：`[profile.release]` 写在 `Cargo.toml`（profile 的权威位置是 manifest）；`.cargo/config.toml` 只保留与构建环境相关、且不绑定特定 CI 路径的项；删除硬编码的 `/home/runner/...` 路径映射与描述旧实现行为的注释。
- 不产出：无。
- 验证：目录与文件与 `02-架构.md` 1.2 一一对应，无空壳文件；`crates/core/Cargo.toml` 不依赖包根；`core` 不引用 `platform`、`app`；`decide` 不引用 `execute`、`platform`；入口只有 `main` 一处；`tests/layer_direction.rs` 存在。

## 4. 依赖关系

```
T0 → T1 → T2 → T3 → T4 → T5 → T6
                    ↘ T7 → T8 → T9 → T10 → T10B
T6, T9, T10 → T11, T12
T11, T12 → T14 → T15 → T16 → T17
T13 与 T10 可并行；T0 提供载体入口的读数，不作为裁剪依据
```

顺序约束：

- **仪器先于业务**：区域摘要器、双 oracle 用例表、故障注入点清单在 T2 之前建起来；T0 的采集物就是它们的第一批输入。
- **一次只留一条路径**：按纵切写（GPT + ext 扩容/收缩 → xfs/btrfs → mkfs/set → move → records/recover），写下一段时删掉上一段的临时脚手架，交付时每种能力只有一条实现。
- **每次提交只做一类改动**，使回退边界可定位。

## 5. 拒侧用例

每条都必须从生产入口喂入，而不是只在测试里构造状态。

| 用例 | 入口 | 期望 |
| --- | --- | --- |
| 脏 ext 收缩，修复后仍小于请求 | `resizefs` | `5`；修复已写目标，记录存在且可回滚 |
| 多设备 btrfs 收缩 | `resizefs` | 不支持，不写目标 |
| 目标被挂载或被占用 | `resize` | 拒绝，不写目标 |
| 未知文件系统收缩 | `resizefs` | 拒绝 |
| 缺少外部工具 | `resize` | 不支持，不写目标 |
| 非 root 写块设备 | `add` | 不支持，不写目标 |
| 非本实现写下的记录 | `recover` | 拒绝，不改目标字节 |
| 记录前缀被截断 | `recover` | 恢复到确定状态 |
| 新表空间不足 | `new` | 拒绝，盘面不变 |
| 分区重叠 | `add` | 拒绝，盘面不变 |
| 写后注入中断 | 任一写命令 | 终态为待恢复，重跑可收敛 |

## 6. 判据自验

由脚本执行（各仪器的 `selftest` 子命令），每个纵切都跑；交付方只保证用例存在、断言完备、采样口径已写死。

同一输入两种变换：

- 只改写法（重命名、拆函数、调整顺序、拆测试）→ 结论必须不变。变了说明判据在读写法。
- 改目标行为（把探针挪回预检、放宽摘要、跳过 oracle、让某族缺表）→ 结论必须变。没变说明判据没测到它声称的东西。

非确定性判据（挂载、工具耗时）预先写死采样口径：重复次数、通过条件、环境是否固定。不得跑完再挑口径。

## 7. 交付前的六个问题

每个任务合入前逐条回答，答不出即未完成：

1. 这一步消除的是哪一类错误，用什么替换；替换物自己会怎么坏。
2. 这条事实在哪一处产生，有几条读路径，有没有一条把缺失折叠成默认值。
3. 判据叫什么，拒侧用例叫什么，从哪个入口喂进去。
4. 有没有"做了一半就对外可见"的窗口；中断后拿什么字段比对续跑。
5. 哪些项未验证，补什么能验。
6. 这一步的"不产出"是否守住；回退边界在哪。

以下形态一旦出现在交付里，按未通过计：

- 把"没查成"折成"没有"或"成功"。
- 闸口晚于不可逆动作：先写后校验。
- 声称回读过，实际只信了退出码。
- 同一条事实在两个地方各自产生。
- 夹具或测试替身比生产实现更严，于是永远绿。
- 检查被关掉，理由不在旁边，也说不清何时恢复。
- 默认值悄悄换了，既无迁移也无报错。
- 注释与行为不符，或出现历史叙事。
- 一次失败被写成单一根因，而其余必要条件未列。
- `rebuild/` 内同时存在两条实现路径。
- 改动了 `rebuild/` 之外的任何路径。

### 10.3 账本与仪器

`plan/baseline/incident-classes.tsv` 的列固定为：`class_id`、`source`、`source_loc`、`category`、`description`、`behavior`、`evidence`、`state`、`reason`。

状态只有四种：

- `已认领`：`evidence` 里每个标记都要落到真实用例（`路径.rs::函数名`）或既有登记（`R####`、`D#`）。
- `差异`：指向 `plan/divergences.md` 中存在的 `D` 编号。
- `已登记缺口`：`owner:SAn`，且该批在 `06` 附录 B 中。
- `范围裁剪`：`reason` 必须六段（`;` 分隔）：不学什么、规范依据、影响面、用户可见后果、替代路径、撤回条件。

`plan/instruments/audit.py` 负责：列数与状态词、证据可解析、M4 与账本同集同状态。门禁 `G11` 执行 `check`；`selftest` 证明缺证据、错状态、缺口无主、裁剪理由不足都会红。

防御面对称 census 由 `audit.py census --source <目录> --tool <名> --version <版本> --out plan/baseline/defense-census.tsv` 生成，口径固定为断言、异常抛出、失败路径 `goto` 三类站点；账本以 `census:<tool>` 引用，数字为 0 也如实入账。

每批 ≤20 类；每类 = 1 行账 + 1 条用例或 1 条差异登记或 1 条六段裁剪理由。超上限加批，不降单类质量。

### 10.5 四条边界

1. 抄行为，不抄实现：认领只要求退出码、输出与盘面效果等价，不要求结构相同。
2. 裁剪项不学：sun/dvh/amiga 等老盘标的防御面不纳入，只登记裁剪理由。
3. 隐式决定逐条判：按「明文 > 既有做法 > 更保守」判序；采纳需登记 D 项与撤回条件，不采纳也要写处置理由。
4. 每批有上限：见 §10.4。

### 10.6 验收判据

换一个人拿 `incident-classes.tsv`，每行都能回答「这个事故或隐式行为，DiskEdit 的对外行为是什么，证据在哪」；答不出的行就是欠账。`G11` 绿只证明账本自洽，不证明覆盖面；覆盖面由 §10.2 的清单逐项勾销。
