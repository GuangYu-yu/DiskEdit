# 01 目标与边界

## 1. 为什么重写

现有实现的三类做法让错误在同一种地方反复出现：

- **写事实靠事后归责**：写入之后是否越过持久边界，由一个运行期标志加一次事后改判给出。于是"已经写了盘，却报告未改动"可以被表达出来。
- **约束靠文本扫描**：一些规则靠检查"某种写法有没有出现"来保证。它只能证明某写法缺席，不能证明该有的东西都在场。
- **语义靠脚本复刻**：集成脚本以人读文本为断言，复刻产品判断。产品侧没有稳定的结构化事实时，测试就只能成为第二实现。

重写要消除的不是这三处代码，而是产生它们的条件：**类型里表达不出来的状态，不要靠约定去守**。

## 2. 目标（可判定）

> 新增一个文件系统族、一条命令、一个拒绝原因时，只改一处数据或一个类型；其余地方不改也仍然成立。

反过来说，任何"改了 A 要记得改 B"的地方都是未完成。判断标准不是行数或分层观感，而是：**编译器或仪器能否替你记住这件事**。

## 3. 等价的定义

五项同时成立才算等价：

1. **命令面**：命令、位置参数、选项名、默认值、值域、互斥关系、用法错误码一致。
2. **退出码**：每个可判定条件落到同一个码（见 `03-行为基线.md` 第 2 节）；本文件第 5 节列出的差异除外。
3. **机器可读输出**：字段名、类型、取值语义一致。人读文本不作契约，除非 `03-行为基线.md` 明确列为判定行。
4. **盘面效果**：同一镜像、同一命令，声明写入区间之外的字节完全一致；区间之内与记录一致且可恢复。
5. **恢复**：本实现的记录可从任意完整前缀恢复到确定状态；不是本实现写下的记录一律拒绝，不改目标字节。

## 4. 不变量

每条都必须有"无法构造"的机制；只有注释的不算。

| # | 不变量 | 机制 |
| --- | --- | --- |
| I1 | 首次写目标字节之后，不可能得出"本次未改动" | 事务状态机 `Unwritten → Armed → {Committed \| RolledBack \| NeedsRecovery}`；拒绝只由 `Unwritten` 构造 |
| I2 | 计划未通过确认与摘要校验，不可能执行 | `ConfirmedPlan` 字段私有，唯一构造点在 `decide::confirm`；执行器只接收它 |
| I3 | 不可能写到计划声明区间之外 | 唯一写入通道 `execute::write(step, regions)`，区间来自该步声明；写后逐区间摘要核对 |
| I4 | 没有已落盘的单步记录，不可能发生目标写入 | 写入要求 `Recorded` 令牌；令牌只由记录层在落盘并 `fsync` 后给出 |
| I5 | 外部事实不可能以缺省值冒充 | `Observation<T> = Known { value, source, seq } \| Unknown { why } \| NotApplicable { why }`；事实位不得用 `Option` 或空集合表达"不知道" |
| I6 | 每条能力事实只有一个产生点 | 文件系统档案表 + 平台能力快照；消费点由矩阵测试穷举 |
| I7 | 退出码只由终态给出 | `report::exit_of(ExecutionState)` 是唯一映射；其他模块不产生码 |
| I8 | 任意记录前缀都能推出确定的可恢复状态 | 帧带序号与 CRC；恢复器是纯函数 `prefix → RecoveryPlan` |
| I9 | 会写目标的工具必须被记录与核对包围 | 工具注册表声明 `Access` 与 `Determinism`；写类工具只由执行器调用 |
| I10 | 未知格式的卷或表不可能被自动清理 | `Evidence::UnknownFormat` 只进入 `inspect` 结论，不进入修复或清理路径 |

## 5. 刻意差异

以下行为与基线不同，每条都必须有测试与撤回条件。除此之外不允许有未登记差异。

| # | 行为 | 理由 | 撤回条件 |
| --- | --- | --- | --- |
| D1 | 写盘之后不可能得出"本次未改动" | 拒绝只发生在未写状态；写后只有部分完成或待恢复 | 出现必须在写后报告"未改动"的真实场景 |
| D2 | 不是本实现写下的记录视为外来，拒绝恢复 | 记录是崩溃恢复的中间物，不是用户数据 | 确认存在必须现场恢复、且无法用写它的版本收尾的记录 |
| D3 | 检查器的原文输出与失败原因可见 | 结论必须可诊断 | 输出体积成为实际障碍且有替代证据 |
| D4 | 需要修复才能判定的操作，先修复再判定；修复一旦写入目标，之后失败一律为部分完成（`5`），不再报拒绝 | 避免修复过程自身改变判定的前提；拒绝只允许发生在未写状态 | 修复被证明不写目标字节 |
| D5 | 退出码只由终态映射 | 消除各调用点自行选码 | 出现终态无法表达的对外契约 |
| D6 | 缺失与空集合不折叠为默认值 | 未观测不等于没有 | 出现必须把未观测当默认值的外部契约 |
| D7 | 载体路径与基线行为等价：基线能跑的，本实现能跑；基线自身不可运行的，同样不提供额外能力 | 等价指行为一致，不是按可运行性裁剪 | 基线载体路径在目标环境可运行而本实现不能 |
| D8 | 不因几何变化改写用户已有的分区类型 GUID | 类型 GUID 是用户数据 | 确认基线确实改写且外部依赖该改写 |

## 6. 完成定义

全部满足才算完成：

- [ ] 16 个命令入口全部实现，每个入口的判定、执行、报告三段齐全（静态可读）。
- [ ] 命令面、退出码、机器输出三项与 `03-行为基线.md` 逐项对应，差异只出现在登记条目上。
- [ ] 每个用例的"声明区间之外字节不变"由区域摘要代码保证，摘要点齐全。
- [ ] 十项不变量各有编译失败用例或矩阵测试，且拒侧用例从生产入口喂入。
- [ ] 记录前缀恢复是纯函数；外来记录被拒绝且不进入写路径。
- [ ] 不存在第二实现：无文本扫描式语义守卫、无脚本复刻产品判断、无进程全局判据。
- [ ] 代码与注释不含外部引用与历史叙事（`02-架构.md` 第 10 节）。
- [ ] 生成物（帮助、能力矩阵、码表）由代码产出，与源码同批更新。
- [ ] 交付附 `05-静态自检.md` 与未执行清单；本次不运行测试，运行类判据一律记「未执行」。
- [ ] `rebuild/` 之外零改动：`git status` 只出现 `rebuild/` 下的路径。

## 7. 范围与硬边界

### 7.1 rebuild 之外只读

仓库根目录及其余一切——`src/`、`tests/`、`Cargo.toml`、`docs/`、CI 配置、`.trae/`——只作为参考与行为基线：不修改、不删除、不重命名、不格式化、不新增文件。任何"顺手改一下外面"的改动都属越界，按未通过计。

### 7.2 rebuild 之内完全自由

`rebuild/` 是一个独立项目。目录结构、模块划分、类型、依赖方向、状态机形态、步骤表达、记录帧布局、测试形态、构建与 lint 配置、文档组织，全部按最优方式重写，不受外部实现的组织方式约束。

### 7.3 冻结的是意图与最终效果

不随实现改变的部分只有两类：

- **怎么用**：命令名、位置参数、选项与默认值、值域、互斥关系、确认与撤销窗口、帮助入口。
- **用了以后得到什么**：退出码、机器可读输出的字段与语义、盘面效果、记录可恢复性。

实现内部的一切选择都属于"怎么做"，不在冻结范围内。判断一条改动是否越界，只看一件事：它会不会让同一个用法示例、同一个参数、同一个退出码或同一个输出字段发生变化。会，就越界；确需变化，必须登记为本文件第 5 节的差异并附撤回条件。

### 7.4 交付范围

**包含**：全部 16 个命令入口、15 类文件系统识别与 7 族操作、GPT/MBR/无表、四种目标形态（镜像、loop、块设备、分区内）、在线扩缩、LVM 链、记录与恢复、帮助与参考生成。

**不包含**：图形界面、网络服务、非 Linux 平台的后端实现（接口保留，实现按平台能力表声明不支持）。

本次**不做范围裁剪**：15 类识别、7 族操作、在线扩缩、LVM 链、载体、记录与恢复、帮助与参考生成全部按等价纳入。与基线不同的行为只有第 5 节的 D1–D8，逐条带测试与撤回条件。

## 8. 停工条件

出现任一条，停下并把问题写成可回答的具体问句，不得先做一半：

1. 某项行为无法从源码确定判据（声明、分支或数据表都读不出它该是什么），且没有已登记的差异条目可覆盖。
2. 某项等价要求与不变量直接冲突，且没有已登记的差异条目可覆盖。
3. 记录格式需要在同一实现内读取第二种格式。
4. 为通过对照而需要修改期望值、放宽区域摘要或跳过独立 oracle。
5. 需要修改仓库根目录的 `src/`、`tests/`、`Cargo.toml` 才能继续。

## 9. 残余风险与逃逸信号

重写也不能消除：第三方工具跨版本差异、文件系统日志语义、外部并发写者、硬件与内核缺陷。它们只能被尽早发现。

| 逃逸方式 | 留下的信号 | 兜底 |
| --- | --- | --- |
| 仪器被改弱或跳过 | 仪器文件出现在改动里 | 判据自验：只改写法结论不变，改行为必红 |
| 新命令绕过管线 | 入口矩阵缺行 | 穷举枚举 + 矩阵测试 |
| `rebuild/` 内出现两套实现 | 旧模块仍在 | 同一次改动内删除旧路径；旧符号检索用例 |
| 手写目标表漂移 | 与代码差集非空 | 尽量由代码生成；手写部分保持最小 |
| 工具写到声明区间之外 | 区域摘要变化 | 摘要不符即失败，不是警告 |
| 该观测的事实未建模 | 后置条件不可观测 | 必须显式 `Unverified`，不得默认成功 |
| 语义正确但数值错 | 双 oracle 不一致 | 期望值不得为迁就实现而改 |
| 证据造假 | 无 | 设计防不了；只到"可重放" |

## 10. 判定原则

- **旧实现是信息，不是理由。** 判断一种形态要不要保留，只看它今天是否成立，不看当初为什么那么写。
- **举证责任在保留方。** 说不出具体理由的形态，按"无理由保留"处理，进入删除候选。
- **不给通过结论。** 交付只写"在覆盖范围内未发现"与「未执行」，不写"已根治""无残留""不会再有同类问题"。
- **结论带版本。** 任何"现在是 X"的判断都写明核对到的提交与日期。

## 11. 撤回条件

出现任一条，说明这次重写没有达成目标，结论作废：

0. 结构性仪器无法给出可判定结论——区分不了"该有的都在"与"有缺失"。
1. 能力清单无法从源码确定，或确定之后仍出现清单外的行为。
2. 任一不变量缺少机制，或缺少从生产入口喂入的拒侧用例。
3. 出现未登记的差异。
4. `rebuild/` 内出现反向依赖、进程全局状态或第二写入通道。
5. 为通过对照而修改期望值、放宽区域摘要或跳过独立 oracle。
6. `rebuild/` 之外的任何路径被改动。
