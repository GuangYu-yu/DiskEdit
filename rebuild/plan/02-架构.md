# 02 架构

## 1. 项目结构

### 1.1 划分原则

- **目录 = 子系统**，名字直说它管什么；目录内不再出现"杂项"文件。
- **文件 = 一个可独立说明的职责**。判断标准：能否用一句话写清"它负责什么、不负责什么"；写不出就是混装。
- **粒度带：单文件 150–600 行**。超过 600 先按职责再拆（典型拆法：解析 / 写入 / 校验 / 定序各一）；低于 100 且与相邻文件同职责的，合并。
- **访问方式不混装**：纯计算与 I/O、读取与写入、决策与执行不放在同一文件。
- **测试就近**：单元测试放同目录 `#[cfg(test)]` 模块或 `tests.rs`；跨模块与端到端放包根 `tests/`；夹具放 `tests/support/`。

### 1.4 依赖与 crate 边界

依赖方向 `app → platform → core`；`app` 内 `cli → report → execute → decide → observe`。`execute` 对 `decide` 的依赖仅限读取 `ConfirmedPlan`、`Plan`、`Step` 这些已铸造好的值，不调用判定函数；分层用例判定的就是这条边，以及 `decide` 不引用 `execute`、`platform`。

**为什么只有纯核成 crate**：

- 纯核无 IO、无时钟、无随机、无环境变量、无全局，API 稳定；"反向依赖不可绕过"是拆分它的唯一必要理由——crate 边界让 `core` 根本无法引用 `platform` 或 `app`。
- `platform` 依赖 Linux、进程与外部工具，当前只有一个消费者；出现第二个消费者或发布需求再拆，否则是提前设计。
- `app` 无外部消费者，拆出去只增加跨 crate 的测试成本与 API 冻结成本。
- `record` 与纯核共享同一批消费者，留在 `core` 内。

包内边界由 `pub(in ...)` 收紧，并由 `tests/layer_direction.rs` 检查：`core` 不引用 `platform`、`app`；`decide` 不引用 `execute`、`platform`。

包根是 `lib + bin`：集成测试、`trybuild` 编译失败用例与文档测试都可用，`main` 只做参数传入与退出码返回；包外消费者只依赖 `lib`，不依赖 `main`。

拆出纯核的代价，按此执行：

- `core` 的 `#[cfg(test)]` 不能与包根互相访问，测试只走公开 API。
- `core` 的 `pub` 面即对外契约，改动须走一次显式的 API 决策，不随手放宽。
- lint 配置集中在 `rebuild/Cargo.toml` 的 `[lints]`，`crates/core` 继承，不另设一套。

## 2. 核心类型与唯一构造点

类型分两类，封闭强度不同，混写会变成假承诺。

**不变量关键类型**——字段私有、构造方法不出定义模块，编译器即可保证唯一构造：

| 类型 | 作用 | 定义与构造所在 |
| --- | --- | --- |
| `TargetId` | 目标身份：种类、指纹、分区选择 | `app/observe/identity.rs`（持锁后构造） |
| `ConfirmedPlan` | 已确认、可执行 | `app/decide/confirmed.rs` |
| `Recorded` | 本步记录已落盘 | `app/execute/token.rs` |
| `ExecutionState` | `Unwritten → Armed → {Committed \| CommittedUnsynced \| RolledBack \| NeedsRecovery}` | `app/execute/state.rs` |
| `Refusal` | 拒绝成因闭集 | `app/decide/refusal.rs` |
| `ExitCode` | 进程边界唯一的码 | `app/report/exit.rs`，只由 `exit_of` 产出 |

**通用类型**——不承担"不可构造"的语义，由所属模块提供 `pub` 构造，唯一性靠 `single_construction` 用例与分层用例守，不是编译器：

| 类型 | 作用 | 构造点 |
| --- | --- | --- |
| `Snapshot` | 一次判定的全部事实，不可变 | `observe::snapshot` |
| `Observation<T>` | 带来源与观测代次的事实容器，任意探测函数都可产出 | `observe` 各探测函数 |
| `Request` | 已解析的用户意图，不含事实 | `cli::parse` |
| `Decision` | `Refuse { kind } \| Plan { steps }` | `decide::decide` |
| `Plan` | 有序步骤 + 摘要 + 版本 | `decide::plan` |
| `Lease` | 目标独占所有权 | `execute::open` |

关键类型的机制：**类型定义在它被铸造的那个模块里**，字段私有，构造方法不带 `pub` 或只对同模块子树可见。Rust 里字段私有的作用域是定义模块及其子模块，`impl` 块本身没有可见性、`pub(in path)` 也只能指向当前模块的祖先——因此跨模块"在别处写构造 impl"不成立。判定与执行共用的值（`Plan`、`Step`、摘要）随 `decide` 走，执行侧只读；执行侧的令牌与状态随 `execute` 走，判定侧不认识它们。`Snapshot`、`Observation`、`Request` 这类通用类型不在此列，它们可以被多处产出，唯一性由用例守。

## 3. 判定与执行

- **判定**只读 `Snapshot`。所需事实为 `Unknown` 时只能产出 `Refuse`，并说明缺哪一项、怎么补；不得取默认值。
- **步骤程序是数据**：`shrink(ext) = [Repair, ProbeMin, ShrinkFs, Verify]`，`grow(xfs) = [Mount, GrowFs, Verify, Unmount]`。次序写在档案表里，不写成代码里的分支顺序。
- 每步声明 `Access ∈ {ReadOnly, WritesTarget, WritesExternalState}`。执行器遇到 `WritesTarget` 前必须已落记录；步骤结束做区域摘要与后置条件核对。
- **执行**只接收 `ConfirmedPlan` 与 `Lease`。失败结论由状态机所在格决定：`Unwritten` 上的失败是拒绝或环境故障；`Armed` 之后的失败是部分完成或待恢复。
- **持久状态与视图分开记**：写盘与记录完成后进入 `Committed`；若内核视图（分区表重读、块设备尺寸）未能同步，进入 `CommittedUnsynced`。`report::exit_of` 一处给出映射：`Committed` → `0`，`CommittedUnsynced` → `5`。
- 写入只有一条通道：`execute::write(step, regions)`，`regions` 来自该步声明。底层写原语接收 `Recorded` 令牌，模块内也无法绕过。
- 外部工具写入（内核重读、在线文件系统扩容）走 `WritesExternalState`：它们不经写通道、没有原像，因此不进入记录的可回滚区间。

### 3.1 在线执行（`execute/online/`）

**模块归属**：`app/execute/online/{mod,flow,guard}.rs`。判定侧只在 `decide::resize::online` 生成一个在线步骤 `GrowFilesystemOnline`；执行侧由 `execute::online::flow::run` 直接消费该步骤，不进入 `transaction` 的写通道。

**职责边界**：

- 只服务**已挂载**目标的文件系统扩容。挂载点由平台端口反查为 `{device, partition, mount}` 事实，判定只消费事实。
- **绝不 umount/remount 用户的挂载**。这是离线形态与在线形态的本质区别：离线形态自行挂载/卸载并登记原像；在线形态直接在现有挂载上运行 `resize2fs`、`xfs_growfs`、`btrfs filesystem resize`。
- `resize --fs-only <挂载点>` 承诺不改分区表，因此在线步骤只扩文件系统；越界与缩容都在任何写盘之前拒绝。
- 在线 FS 步骤不登记原像、不可回滚：工具一旦启动，失败一律按部分完成（`5`）报告；记录目录不因此新增条目。它也不进入 `transaction` 的位图/摘要核对。
- 在线路径仍取得整盘租约并复核身份，与离线路径互斥；租约只用于串行化本实现的写操作，不改变用户挂载。

**占用闸语义**：

- "目标必须空闲"只属于离线形态。离线形态要求 `occupancy` 为 `Known` 且未被占用，因为要独占挂载与写表。
- 在线形态的目标本来就挂载着，准入**跳过占用闸**；取而代之的是：挂载事实必须 `Known` 且为 `Mounted`、设备必须是分区、整盘租约可取、身份一致、目标分区不是活动 swap、内核分区视图与盘上表同尺寸、btrfs 必须单设备。

**拒绝路径清单**（全部在任何写盘之前）：

| 成因 | 出口 |
| --- | --- |
| 目录未挂载 / 多重挂载 / 挂载设备不是分区 / 匿名设备无法映射到单盘 | 拒绝 `3`（匿名设备为不支持 `6`） |
| 挂载点在持锁窗口内改指别的设备 | 拒绝 `3` |
| 整盘租约取不到、整盘打开或指纹读取失败 | 未写盘的环境故障 `4` |
| 目标分区处于活动 swap | 拒绝 `3` |
| 存在未完成的记录 | 拒绝 `3` |
| 内核分区尺寸与盘上表不一致（视图过期） | 未写盘的环境故障 `4` |
| btrfs 跨多设备 | 不支持 `6` |
| 该文件系统族没有在线扩容工具、请求越界或要求缩容 | 拒绝 `3`（族的档案表给出结论） |
| 工具缺失 | 不支持 `6` |
| 工具启动失败 | 未写盘的环境故障 `4` |
| 工具运行后非零退出、或扩容后尺寸未到分区末端 | 部分完成 `5` |

**与记录模型的关系**：在线步骤没有表区写入，因此不产生原像帧；若将来在线形态包含表区步骤，该表区仍按 `transaction` 登记原像，文件系统步骤仍标记为不可逆。恢复器对不可逆帧只做表区回滚，不回收已写入的文件系统数据。


## 4. 事实与观察

- 一条事实 = 值 + 来源 + 观测代次。代次让"过期"可判定：执行期重探所得代次必须不早于快照代次，否则按"目标已变"拒绝。
- 典型事实：`fs_kind`、`fs_state(clean/dirty/unknown)`、`min_bytes`、`occupancy`、`mount_facts`、几何、工具版本。
- `occupancy = Known(Free) | Known(Held { holders: NonEmpty<Holder> }) | Unknown`。空集合与"不知道"在类型上不同。
- 未知不阻塞全部操作：`check`、`inspect` 可带 `Unknown` 继续；写类命令所需事实为 `Unknown` 时拒绝。

## 5. 文件系统档案表

```rust
// crates/core/src/fs/profile.rs
pub struct FsProfile {
    pub kind: FsKind,
    pub readback: Readback,      // None | Label | LabelAndUuid | Full
    pub grow: StepProgram,       // 空 = 不支持扩容
    pub shrink: StepProgram,
    pub set_attrs: SetProgram,
    pub check: CheckProgram,
    pub min_size: MinSizeProbe,  // NotAvailable | Tool(&'static str)
}
```

在线扩容与其它能力一样按族给出结论：`catalog::online_grow(kind) -> OnlineGrow`，取值 `Device(程序)`（如 `resize2fs <device>`）、`MountPoint(程序)`（如 `xfs_growfs <挂载点>`）或 `Unsupported(原因)`。匹配穷尽，漏写一族编译失败。

档案表只描述族的能力与步骤程序，不接收 `Snapshot`——`Snapshot` 属于 `app::observe`，`core` 不能引用它。识别由 `app/observe/filesystem.rs` 完成：探测签名得到 `Observation<FsKind>`，再按 `kind` 查档案表；档案表只回答"这一族能做什么、按什么顺序做、用哪个工具"。

- 新增一族 = 加一行数据 + 一个适配器。`match FsKind` 穷尽，漏写编译失败；能力性分支只允许出现在 `catalog.rs`。
- 工具注册表每项声明：族、用途、`Access`、`Determinism`、版本探测、错误分类。所有外部工具调用经同一执行器（argv 记录、有界捕获、退出分类）。
- `Determinism::NonDeterministic` 的结果不得作为唯一判据，必须有第二个 oracle 或区域摘要。

## 6. 持久记录

```
头：magic | 格式标识 | 目标指纹 | 几何代次 | 计划摘要 | 头 CRC
帧：序号 | 类型 | 区间列表（偏移/长度/原像摘要） | 意图 | 帧 CRC | 完成标记
```

- 只追加，帧序号连续；不完整帧不视为已提交。
- 恢复计划 = 完整前缀 → `回滚（写回原像） | 重放（重做该步） | 需人工（证据冲突）`。恢复器是纯函数，不读目标、不看时钟。
- 格式标识不匹配：按外来记录拒绝，不读后续帧，不改目标字节。实现内不存在第二格式的读取分支。
- 头部记录的计划摘要与执行前重算值不一致：拒绝执行。
- 头里的目标指纹与几何代次由执行期在装载记录时与当前快照比对：不一致即不接受该记录。纯恢复函数只接收已校验的头，自身不读目标。
- 原像只覆盖表区。搬移类操作已写的数据不回滚、不回收、旧位置不清零；这一点由记录在搬移前标记为不可逆，恢复器据此只做表区回滚。

## 7. 报告与退出码

- 退出码七值：`0` 成功；`1` 写目标字节前的不变量破坏或内部错误；`2` 用法与解析错误（含缺 `--yes`）；`3` 拒绝或记录损坏；`4` 已进入执行且目标字节未变的 I/O 或环境故障；`5` 部分完成、待恢复，或持久状态已达成但内核视图未同步；`6` 能力不支持。
- `report::exit_of` 是唯一映射。判定顺序与逐格谓词以 `03-行为基线.md` 第 2 节为准。
- 机器输出由结构体序列化，文本与 JSON 消费同一结构；不存在手拼 JSON。
- 每个拒绝成因有一条固定的"下一步"文案；新增成因不写文案则编译失败。

## 8. 命令行

- 声明式定义：命令、形态、位置槽、选项、值域、互斥、确认规则、能力需求、撤销窗口都在同一份声明里。
- `argv → Request` 单向；解析层不认识目标与文件系统。
- 帮助、用法错误、参考文档、能力矩阵都从同一份声明生成。

## 9. 文档与生成物

退出码表、命令矩阵、能力矩阵、工具表由代码生成到 `docs/en/` 与 `docs/zh/`，CI 比对工作树。散文只写不变量、决策与任务；不写"实现现在如何"——那由生成物和代码回答。

## 10. 代码约定

- 注释只描述当前行为：说清"这段做什么、边界条件是什么"，不写谁改过、为什么改、参考哪份文档。
- 禁止历史叙事词：原、旧、改为、修复、兼容、迁移、v2、临时、暂时。
- 禁止在代码与注释中出现外部文档路径或章节号；`plan/` 与仓库根 `src/` 不在任何引用范围内（生成器写入 `docs/` 属于产出，不是引用）。
- 命名即契约：`ConfirmedPlan` 表示已确认，不得承载未确认语义；`Unknown` 不得被当作默认值使用。
- 冷读标准：把任一文件单独交给未参与的人，他读完能说出这段做什么、失败会怎样、边界在哪，不需要追问背景。
- 无进程全局：不用 thread-local、静态可变、编译期路径常量承载判据；需要注入的依赖走端口参数。
- 错误只在一处分层：`Refusal` 由判定层产出，`ExecutionState` 由执行层产出，二者不共享构造入口。

## 11. 测试与仪器

### 11.1 形态：只有 Rust，没有 shell

测试全部是 Rust。需要 root、loop、挂载、真块设备或外部工具的用例，同样由 Rust 集成测试调用这些程序完成，不写成 `.sh`。

- 理由一：脚本没有类型，断言靠 grep 人读文本，产品的稳定事实一旦变形，脚本要么静默放过，要么报错指不到原因。
- 理由二：脚本的失败形态是结构性的——可被 `&&` 跳过、可吞输出、可按固定行数定位；这些不是作者疏忽，而是"用文本描述行为"必然带来的。
- 理由三：脚本是第二套语义实现。同一判断在 Rust 与脚本里各写一遍，两边漂移时没有任何仪器能发现。
- 因此：不引入 shell 测试目录，不用 shell 复刻任何产品判断；外部程序一律经 `Command` 直接调用，argv 与退出码由类型化的封装返回。

### 11.2 六层

1. **纯核属性测试**：区间不重叠、几何换算、编解码往返、前缀恢复。无 IO，放在 `core` 内的 `#[cfg(test)]`。
2. **编译失败测试**：I1、I2、I5 各至少一条，`tests/ui/` + `trybuild`。
3. **契约测试**：命令面与用法错误、退出码逐格、JSON 字段与类型。不碰目标字节。
4. **用例表 + 双 oracle**：每个用例是数据，产品 JSON 与独立权威（`fsck -n`、工具 `-n`、sysfs）对照。
5. **区域摘要**：每个写类用例结束后，声明区间之外的字节摘要必须不变。
6. **故障注入**：每帧前后、每个工具写前后注入失败，断言恢复器把状态推进到确定格。

### 11.3 用例表

用例是结构体，不是脚本函数：

```rust
struct Case {
    id: &'static str,          // 与任务编号对应
    recipe: Recipe,            // 镜像配方：表类型、文件系统、大小、损坏形态
    argv: &'static [&'static str],
    precondition: Precondition,// 需要 root / loop / 特定工具
    expect_exit: u8,
    expect_json: Option<Expectation>,  // 字段级期望，不比对整段文本
    invariants: &'static [Invariant],  // 区域摘要、记录可恢复、GUID 不变等
}
```

- 一个 `runner` 消费整张表；新增用例只加一行数据。
- 期望值是字段级的：`exit==5`、`json.holders` 非空、区间 `[a,b)` 未变；不比对整段输出，也不比对行号。
- 每个用例都有 `id`；失败消息打印 `id`、命令、期望、实际、以及可复现的配方名。

### 11.4 前置条件与特权

- 前置条件不满足时，用例结果为 `NotApplicable { why }`，不是静默跳过。
- CI 特权作业跑完后，断言"应当适用的用例集合 = 实际执行的用例集合"；差集非空即失败——这条防止"因为环境缺失而长期不跑的用例"。
- 镜像文件类用例不需要 root：目标可以是普通文件，绝大多数命令面与记录用例都在这一档。
- 需要 root 的档：loop 设备、真块设备、挂载、在线扩缩、LVM 链。它们放在同一张用例表里，只由 `precondition` 区分。

### 11.5 结构仪器

- **集合相等**：类型清单与 `plan/` 的清单一致；每个铸造点在登记表恰有一行；`FsKind × 操作` 无缺席格；声明的 lint 在 `Cargo.toml` 的 `[lints]` 中启用。
- **入口穷举**：命令声明的入口集合 = 用例表中的入口集合 = 分发器的分支集合。
- **禁止第二实现**：不存在文本扫描式语义守卫、不存在 shell 或测试复刻产品判断、不存在进程全局判据。这三条无法完全类型化，保留为静态用例，且每条写明替代不了的类型是什么。
- **判据自验**：只改写法（重命名、拆函数、调序）结论不变；改目标行为（挪探针、放宽摘要、跳过 oracle）结论必变。此验证由执行测试的人运行，不写入交付结论。

## 12. 防逃逸

| 逃逸方式 | 信号 | 兜底 |
| --- | --- | --- |
| 仪器被改弱 | 仪器文件出现在改动里 | 判据自验 + 独立复核 |
| 新入口绕过管线 | 入口矩阵缺行 | 穷举枚举 + 矩阵测试 |
| `rebuild/` 内双实现残留 | 旧模块仍在 | 同一次改动内删除旧路径，旧符号检索用例 |
| 能力判断散落 | 出现 `catalog.rs` 之外的能力性 `match` | 静态断言 |
| 该观测的事实未建模 | 后置条件不可观测 | 必须显式 `Unverified` |
