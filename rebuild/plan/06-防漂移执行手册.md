# 06 执行手册

> 本文件是执行协议，不是设计说明。`01`–`05` 定义"做什么"，本文件定义"谁来做、按什么顺序做、每一步留下什么证据、什么情况下必须停工"。
> 与 `01`–`05` 冲突时，以本文件为准；本文件未覆盖的行为，一律视为未定义，必须停工提问。
> 本文件中的"必须/禁止/只能"没有例外。出现"应该/可以/酌情/视情况/大致"这类词，一律按"未定义"处理。

## 0. 这份手册靠什么防漂移

上一轮重写出的代码，经静态审查有 198 条发现。它们的根因不是执行者不守规矩，而是三件事：

| 根因 | 上一轮的事实 | 这一轮的办法 |
| --- | --- | --- |
| 规范是人工摘要，本身就不全 | 旧版有 974 个退出码构造点、581 个拒绝点；行为基线只写了 16 条，拒侧用例只有 11 条 | 规范由机器从旧版源码数出来并冻结（`baseline/census.json`、`baseline/refusal-sites.tsv`），摘要与冻结结果不一致以冻结结果为准 |
| 对错靠模型自述 | 等价对照在没设基线二进制时一条没跑却返回绿；"已核对"没有任何记录 | 所有门禁经 `plan/instruments/gate.py` 下结论，没跑够数就是红；期望值来自旧版二进制的实际输出，不来自任何模型的阅读 |
| 检测只从一个方向看 | 只枚举新版的拒绝点，只能发现"新版变严"；"旧版拒绝、新版放行"和"旧版有、新版连拒绝都没有"没人查 | 普查器从旧版一侧出发：命令面差集、每个旧版拒绝点必须有人认领 |

一句话：**模型只做机器判不了的事；凡是机器能判对错的，结论由脚本给。**

## 1. 谁做什么

| 角色 | 只做 | 不做 | 它的产出怎么验收 |
| --- | --- | --- | --- |
| 强模型（最贵的那档） | 三样东西：① 出题器（场景生成器与镜像配方）；② `core` 的类型骨架与编译失败用例（`01` §4 的 I1–I12）；③ 仪器（`plan/instruments/`）。外加：裁决脚本报出的差集、回答停工问句 | 不写纵切的业务代码；不改门禁表里的最少通过数来迁就实现 | 仪器以自检验收（`selftest`）；类型骨架以编译失败用例验收；裁决必须落到 `divergences.md` 或某条 B，不落在对话里 |
| 执行模型（任意档次，可以很弱） | 按纵切写用例与实现；填 `refusal-map.tsv`；填附录 A 的表 | 不改 `plan/instruments/`、`plan/baseline/census.json`、`plan/baseline/refusal-sites.tsv`、`plan/gates.tsv` | 只看门禁记录 `plan/evidence/*.log.json`。它说的任何话都不是依据 |
| 脚本 | 下结论：普查、差集、认领、通过数、残留检索 | — | 自己先自检；自检红则一切门禁作废 |
| 旧版二进制 | 提供标准答案：同一镜像、同一命令，它的退出码、输出、盘面摘要就是期望值 | — | — |
| 人 | 跑一条重档命令；决定差异登记；决定起点（§2 第 4 条） | — | — |

开销最大的那档只花在三样小东西和裁决上。900KiB 的业务代码由便宜的模型写，写错了由脚本发现，不由强模型通读发现。

## 2. 开工前置（缺一条不开始）

1. **执行机器**：一台 Linux 机器，有 root、`rustup` 的 stable 工具链、各文件系统工具、可用的 loop 设备、Python 3.10 以上。编译档必须在它上面跑：别的平台会把 Linux 后端整块条件编译掉，那种绿不算数。
2. **旧版二进制**：从仓库根以 release 构建一次，路径写进环境变量 `DISKEDIT_BASELINE`。
3. **仪器可用**：在 `rebuild/` 下执行 `python plan/instruments/gate.py all --plan plan/gates.tsv --who model --only G0,G0b,G0c,G1`，四项全绿。
4. **起点**：由人在开工令里指定，二选一。
   - A 清空重来：保留 `plan/`，其余目录清空后从骨架开始。
   - B 逐纵切整体替换（默认）：不修补现有文件。轮到某个纵切时，按规范把它涉及的文件整份重写；没被任何纵切认领的旧文件在 S9 删除。
   两个选项都不允许"在现有代码上改几行让它过"。
5. **起点 B 的移出动作**：S0 必须先把现有实现移出编译范围（排除模块或工作区成员，保留只读副本供取数与基线），并让 G2 在只剩骨架时通过。否则 S1–S8 期间 `rebuild/` 内会同时存在两套实现，与 `01` §7 冲突；做不到就改用 A。

## 5. 门禁

门禁全部定义在 `plan/gates.tsv`，共 7 列：门禁名、谁跑、类型、最少通过数、必需环境变量、必需文件、命令。

**执行方式只有两条命令**（在 `rebuild/` 下）：

```sh
python plan/instruments/gate.py all --plan plan/gates.tsv --who model --exclude G1b,G6b   # 每个纵切
python plan/instruments/gate.py all --plan plan/gates.tsv --who human                      # 每个纵切，人跑
python plan/instruments/gate.py all --plan plan/gates.tsv --who model                      # 交付前，含全集门
python plan/instruments/gate.py status --evidence plan/evidence --gates plan/gates.tsv      # 交付前：缺记录、有红或内容指纹不符即退出 1
```

| 门禁 | 查什么 | 红的条件 |
| --- | --- | --- |
| G0、G0b | 两支仪器自己 | 自检任何一条不过 |
| G0c | 文档一致：表格列数、编号全集、重复段、交付定义 | 任一处不一致 |
| G1 | 旧版源码没变 | 与冻结结果不一致 |
| G1b | B/I/D 覆盖：每条都有带 `// covers:` 的用例 | 有任一编号没有用例 |
| G2a–G2c | 格式、clippy、编译 | 任何告警或错误 |
| G3a–G3d | 不变量：唯一构造点、依赖方向、入口登记、编译失败用例 | 通过数低于登记数 |
| G4a–G4d | 纯核用例、命令面契约、用例表、残留检索 | 同上；或出现 `NotApplicable` |
| G5a、G5b | 新版命令面与旧版差集 | 有未登记差异 |
| G6 | 本轮 `refusal-due.tsv` 里的旧版退出码构造点都有认领人与用例，且用例带 `// covers: R*` | 有任一行缺认领、缺依据、缺用例，或指不到带 `covers: R*` 的用例 |
| G6b | 全集：旧版 974 个退出码构造点都有认领人与用例（交付门） | 同上，逐条对全集 |
| G9 | 提交外足迹：基线（`plan/footprint.base`）之后只许出现 `rebuild/` 下的路径，工作区同样 | 有任一越界路径 |
| G10 | 提交信息：`<前缀>[ <范围>]: <说明>`，无 `wip`/`tmp`/`fix`/`update`/`杂项` | 任一条不合规 |
| G11 | 事故与隐式行为账本：列数与状态词、证据可解析、M4 与账本同集同状态 | 任一行缺归属、缺证据、状态不一致，或被裁剪行没有六段理由 |
| G7 | 等价对照（人跑） | 没设 `DISKEDIT_BASELINE`；通过数低于登记数；有失败；有被忽略 |
| G8、G8b | 全量测试与 release 构建（人跑） | 同上 |

运行档的插入点：S5（写路径齐）与 S8（LVM/载体齐）结束时各插一次完整运行档（G7/G8/G8b 加真实镜像与特权用例），不等到 S9；此前的纵切仍按每片 G6 与本地等价场景扩，不跳过。

规则：

- **最少通过数是下限。** 用例变多就上调。下调必须在提交说明里写明删了哪条用例、为什么；写不出就不许下调。
- 表里写"待钉"的数字，由强模型在该测试首次落定时填成实数。没有实数之前那一行恒红。
- 测试二进制名以 `cargo test --list` 为准。对不上就改门禁表里的名字，不许为了让名字对上而新建一个空测试。
- 任何一条红，回到纵切修根因。禁止改期望值、放宽摘要、跳过 oracle、给用例加 `ignore`。
- 门禁表与两支仪器只能由强模型改。执行模型的提交若触及 `plan/instruments/`、`plan/gates.tsv`、`baseline/census.json`、`baseline/refusal-sites.tsv`，整批作废。
- G5b 依赖 `target/command-surface.json`；该文件由 S0 产出。S0 未产出前 G5b 保持红，不得手写该文件。
- G1b、G6b 是全集门，只在交付前跑；纵切按 `--exclude G1b,G6b` 执行，G6 只检查本纵切已追加进 `refusal-due.tsv` 的 R 行。

## 6. 证据

证据不再是手写的块，而是门禁自动写出的记录 `plan/evidence/<门禁名>.log.json`，内容含命令原文、退出码、各项计数、工作树内容指纹、提交号、时间、结论与红因；同名 `.log` 是完整输出。

附录 A 各表的"证据"一列只填记录文件名。手工写"已通过"无效；记录里的内容指纹与当前工作树对不上无效，提交号只作参考。

## 7. 纵切流程

一次只做**一个纵切**：一条命令或一个能力族，从判定到执行到报告，加上它的拒侧用例。顺序见附录 B。纵切未过全部门禁，不得开始下一个。

**禁止**在同一时刻改两个纵切；**禁止**按文件并行——上一轮每份文件局部都合格，却没有谁对跨模块的不变量负责。

每个纵切固定九步：

1. **圈定**（执行模型）：在 `refusal-map.tsv` 里找出本纵切要认领的 `R` 行；在附录 A 的三张表里找出本纵切涉及的 B、I、D 行。圈不出来的行为不许写。
2. **先红**（执行模型）：对每条 B、每条 I 的反例、每条 D 的撤回条件写用例。用例从生产入口喂入，文件头写 `// covers: B21, I11`。写完立刻跑，保存失败输出。用例没先红过，视为没写。
3. **认领**（执行模型）：给每条 `R` 行填"新版认领、依据、用例"，并把本纵切涉及的 R 编号追加到 `plan/baseline/refusal-due.tsv`（一行一个，只增不减）。依据只能是两种：旧版源码位置，或基线二进制的实跑记录。"我觉得旧版大概会拒绝"不是依据。
4. **实现**（执行模型）：只经唯一写通道；所有拒绝分支在任何写盘之前返回；先落记录后写目标；写完回读；退出码只由终态映射。
5. **模型门禁**：`gate.py all --who model --exclude G1b,G6b`。红了回到第 4 步。
6. **人跑门禁**：`gate.py all --who human`。人执行一条命令，把结果留在 `plan/evidence/`。
7. **差集裁决**（强模型）：只读脚本报出的差集与红因。每一条要么修实现，要么按 §10 登记，要么落到一条新的 B。三样都不落，纵切不算完。
8. **填表**：把附录 A 三张表里本纵切的状态从 `空` 改为 `绿`，证据列填记录文件名。
9. **提交**：一次提交只做一个纵切。信息格式 `S{纵切号} {范围}: {做了什么}`，正文写不产出与影响面。禁止 `wip`、`fix`、`update`、`杂项`。

## 8. 对抗矩阵

每一格至少一个用例，从生产入口喂入。空格即为缺陷。用例名 `adv_<维度>_<场景>`，文件头写 `// covers: Bx`。

| 维度 | 必须覆盖的格子 | 对应 |
| --- | --- | --- |
| 占用证据源 | 挂载表、交换区表、loop、阵列成员、holders、多设备 btrfs 成员各一格；前五格再分三种：文件不存在、权限拒绝、内容不可解析。每一种都必须得到"已占用"或 `Unknown`，不得得到空集 | B4、B17、I5 |
| 记录 | 空、完整、截断、撕裂、外来 magic、身份不符、外来条目混入、目录不存在、旧版在途记录在场 | B8、B23、D2 |
| 回滚 | 目标字节未变、目标字节被外部改、原像为空、记录已提交、写一半中断、双断点 | B7、B24 |
| 放弃与清理 | 有记录、无记录、记录属于别的载体、外来布局、外来条目；删除前回读不匹配 | B8、B23 |
| 几何 | 写入越尾、偏移溢出、LBA 下溢、4Kn 与 512e 错配、非 2 的幂扇区、条目结束早于起始 | B18、B19、B20、I11 |
| 搬移 | 源与目标重叠且目标在前、源在前；自重叠续跑；游标、前缀摘要、几何快照缺一 | B14、B21 |
| 在线 | 已挂载、活动 swap、btrfs 多设备、租约取不到、内核视图过期 | B28、I12 |
| 外部步骤 | 确定完成、确定未开始、结果不确定；不确定时不得重试 | B27、I12 |
| 中断 | 写前、写中、写后各一格，且每格验证"重跑可收敛" | B16 |
| 并发 | 同目标双进程、锁内改指、记录目录被替换、判定与打开之间路径被换 | B3、B5、B9 |

矩阵不是封闭清单：审查报告里每一条 S1、S2，以及此后每一次新发现，都必须在矩阵里占一格。上一轮已经出过事而这里没有对应格的，先补格再动手。

## 9. 检测器怎么读

| 检测器 | 它抓什么 | 抓不到什么 |
| --- | --- | --- |
| `census.py check` | 旧版源码变了而基线没重冻 | 旧版变了但构造点文案没变的情况（计数与摘要都没变时） |
| `census.py surface` | 新版少命令、少形态、少选项、改默认形态、改确认门 | 选项的语义变了但名字没变；人读文案的变化 |
| `census.py owners` | 旧版某个拒绝点在新版没人认领，或认领指不到带 `covers: R*` 的用例 | 用例存在但断言空转（靠 `gate.py` 的通过数与变异自验兜底） |
| `census.py covers` | B1–B28、I1–I12、D1–D12 有编号没有 `// covers:` 用例 | 有用例但没测到该条语义 |
| `census.py docs` | 表格列数、编号全集、重复段、交付定义不一致 | 语义层面的自相矛盾 |
| `gate.py` | 门禁空转、通过数不足、被忽略、`NotApplicable` | 测试本身断言错了 |
| G7 等价对照 | 喂进去的场景里，新旧退出码、输出、盘面摘要不一致 | 没喂进去的场景 |

第三列就是静态审查的置信边界：**这些检测器全部绿，只说明"在喂进去的场景与枚举到的构造点范围内没发现差异"。** 出场景清单的是出题器，它是强模型写的那三样之一，也是唯一决定覆盖上限的东西。

## 10. 差异登记（唯一合法路径）

任何"基线有、新版不做或做得不一样"的行为，只能这样处理：

1. 用基线二进制复现该行为，命令与输出存进 `plan/baseline/`。
2. 在 `divergences.md` 加一行，四项齐备：行为、理由、撤回条件、测试位置。
3. 命令面差异再把 `census.py surface` 打印的那一行原文抄进 `baseline/surface-allowed.txt`，行尾用一个制表符接 D 编号；该 D 必须已在 `divergences.md` 存在，否则按未登记拒绝。
4. 写两条用例：默认行为被改变的那条，与撤回条件满足时的那条。
5. 同步 `01` §5 的摘录。

任一步缺，不得改实现。引不出基线证据的"做不到"只能记进 `05` 的未执行清单，不得登记为差异。

已登记的共 12 条。其中 D2（记录格式换代）是刻意的：不读取、不迁移旧格式，目标上有旧版在途记录时写命令拒绝且不改目标字节。

## 11. 停工与提问

触发条件（任一即停）：

- 一条 B 写不出可观测判据（输入、动作、期望的退出码或字节或记录状态）。
- 旧版行为无法从源码位置或基线二进制确定。
- 两条要求互相冲突。
- 需要改 `plan/instruments/`、`plan/gates.tsv` 或冻结结果才能继续。
- 需要放宽摘要、跳过 oracle、改期望值、下调最少通过数才能绿。
- 需要第二条写通道、第二种记录格式或第二处同能力实现。
- 检测器报了差集，而差集既不该修实现、也没有基线证据可以登记。

提问格式（缺项不得发出）：

