# 处置判断协议（全量 11,918 行）

**阶段纪律：本阶段禁止任何代码改动（crates/、src/、tests/ 只读）。产出仅限 plan/disposition/ 下的 tsv/md。**

## 总纲（用户既定方针）

- 彻底等价抹平短板差异：参考工具（fdisk/parted/gdisk/e2fsprogs/…/旧版实现）有大量长期实践，凡属真实行为都要给出归属；
- 完全按旧版命令用法、意图与效果，但实现方式最现代化、职责分明；
- 不照搬老古董：可有取舍，但取舍必须登记（差异/裁剪），不得静默丢弃。

## 权威依据（判断时按此优先级取证据）

1. `plan/baseline/incident-classes.tsv` — 49 条 SA 行（已认领/范围裁剪 = 本实现已定的范围与行为）
2. `plan/baseline/refusal-map.tsv` — 拒绝面映射
3. `plan/06-防漂移执行手册.md` — 语义边界
4. 旧版实现源码 `/workspace/src`（只读参考：旧版做了什么）
5. 新实现源码 `crates/`、`src/`（只读：现在有什么）
6. 参考工具源码与文档行号（reference 账本行内已有）

## 四态定义（batch tsv 的 state 列）

| 态 | 定义 | note 必填 |
| --- | --- | --- |
| 认领 | 行为本实现已有（引 SA id / 代码路径 / 测试锚），或应有且纳入工作项（note 标 `待实现`） | 依据（SAxx-xxx / 代码路径 / 参考行号）；待实现项另加根因标签 |
| 拒绝 | 在范围内但有意不采纳（有取舍理由） | 理由 + 依据 |
| 差异 | 与参考行为不同且同为范围内，需登记 divergence | `D-建议:<一句话>`（编号由主控统一登记） |
| 裁剪 | 绑定本实现不存在或已裁剪的特性（交互 prompt、老盘标、菜单式恢复等） | 引 SA id 或特性依据；整批含裁剪行时创建同名 md 写撤回条件 |

## 判断流程（每个批次）

1. 读批次 tsv 的 row_id/ledger → 在 `plan/baseline/reference/`（sites 按 `<tool>.tsv`）查全字段；
2. 按行 finding/category/risk 归组；同批若出现两种结论，在行 note 标 `建议拆分:<新批名>`，不强拆；
3. 逐行给四态 + note；同批同结论可只在一行写完整 note，其余写 `同上`；
4. 该批若含裁剪/差异行 → 创建 `plan/disposition/<批次路径>.md`（判断/依据/撤回条件）；
5. **不改动 queue.tsv**（主控统一重算）。

## 根因标签（工作项必标，全局汇总用）

`耦合读判写` / `缺校验(签名/边界/容量)` / `缺回读证实` / `提示面缺失` / `交互面裁剪` / `依赖工具面` / `内核视图` / `身份(UUID)` / `防御断言替代错误` / `架构差异-多虑`

每个待实现项格式：`row_id | 行为一句话 | 标签 | 根因一句话 | 建议硬约束（门控/闸门/仪器/测试/架构其一）`

## 产出

1. 各批次 tsv 全部翻态（不留待判，除非信息确实不足——note 写明缺什么）；
2. `plan/disposition/reports/chunk-<名>.md`：待实现工作项清单 + 差异建议 + 拆分建议 + 本批统计（认领/拒绝/差异/裁剪计数）。
